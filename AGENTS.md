# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Static Vite + three.js site, deployed by Vercel's Git integration (PRs get previews, `main` is production). There is no deploy workflow in this repo; Vite `base` is `/`.
- Body systems are data-driven layers (`src/layers.js` + `src/data/<system>.json`); README "Adding a body system" has the steps. Part info is keyed by the mesh name with "left"/"right" stripped. Optional generic layer fields (sub-`groups` and `groupToggles`, `flow`, `effects` such as the haze glow, a guided `tour`, the `depthLevels` peel slider and `movements` picker built by `src/layer-controls.js`) are documented there too; any haze is decorative and must stay labeled "Illustrative". Every layer must fill a `notShown` list (README step 4; `scripts/not-shown.test.mjs` enforces it); when a change adds or drops parts, update that list. Each part lives in exactly one layer (`scripts/one-home.test.mjs`); a layer that needs another's part lists it as `other-system` with that `layer` instead of showing it too. System models load lazily on first toggle unless the layer sets `preload: true` (only Skeletal does).
- `public/models/*.glb` are generated by `npm run fetch-data && npm run build-models` and committed. Don't hand-edit them; change `scripts/build-models.mjs` and rebuild. Assets build in `ASSETS` order and a new one goes last so the earlier GLBs stay byte-identical; even so `reproductive.glb` can come out with different bytes, so commit only the GLBs your change meant to change. Each file has its own license (README "Anatomy model"); the CC BY-NC-SA ossicles, inner-ear nerves and Sense organs ear parts (`senses-ear.glb`) must stay in their own GLBs. The footer credits are a license requirement, so keep them.
- Parts BodyParts3D lacks, or models only in pieces (the neck vessels bridged by `scripts/circulatory-model.mjs`), come from Z-Anatomy: `scripts/extract-z-anatomy.py` runs in Blender and writes `data-sources/z-anatomy/` (committed), which the model build reads. Read evaluated meshes for objects with modifiers, or they export as stubs. A full extract run (local Blender 4.2) rewrites unrelated committed outputs (ossicles, parotids, the `.obj.gz` files) with different bytes; commit only the files your change meant to add or change. The deep brain structures in `nervous.glb` are BodyParts3D meshes (`DEEP_BRAIN` in `scripts/build-models.mjs`), not Z-Anatomy; the small nuclei neither has are surfaced from the Allen Human Reference Atlas label volume (`.cache/allen/`, fetched by `npm run fetch-data`) and fitted onto that brain by `scripts/allen-model.mjs`. A part placed from a population-average atlas sets `approximate: true` in its part entry, which the UI labels.
- Layer meshes must use `layerMaterials()` in `src/viewer.js` and be picked through `#hits()`, so the close-zoom cutaway (camera-distance discard) applies to both what you see and what you click.
- Viewer mesh visibility (sub-group toggles, peeling, movement emphasis) is applied in one place, `#applyDisplay` in `src/viewer.js`; set it through `setGroupVisible`/`setPeeled`/`setEmphasis`, not `mesh.visible`, or the controls overwrite each other.
- `npm run build-models` ends with `npm run check-placement` (also in CI, `.github/workflows/check.yml`): every layer in `src/data/` must stay under the skin, out of solid bone and out of other layers' parts. The build fixes placement in `scripts/settle.mjs` (and `fitLine`/`fitPoints` in `scripts/nervous-model.mjs` for nerves, `scripts/lymphatic-model.mjs` for lymph nodes); per-vertex settling crumples thin tubes, so Circulatory settles by a smooth field (its asset's `smooth` option), guarded by `scripts/circulatory-shape.test.mjs`; allowances (bone `PASSAGES`, skin `ON_SKIN`, `NESTED`/`YIELDS`, and the check-only `RESIDUALS`/`SKIN_RESIDUALS`/`KNOWN`) live in `scripts/passages.mjs` and `scripts/overlaps.mjs` and must stay named and bounded. A full model build takes over an hour of CPU, so don't rebuild just to tweak check-only lists (`RESIDUALS`, `KNOWN`, `NESTED`), which the build does not read. The build settles in the Z-up source frame and the check measures the shipped GLBs in the Y-up frame, so `Envelope`/`Solid` in `scripts/solid.mjs` must answer the same in both (centred voxel grid, deterministic ties); a frame-dependent change there shows up as sub-mm skin failures the build cannot fix. The build re-reads `src/data/*.json` while it runs, so don't edit those files until it finishes.
- Page-wide keyboard shortcuts must skip keys while the user types: reuse `isTypingTarget` from `src/keyboard-nav.js` (the WASD movement guard) rather than writing another check.
- The part search lists meshes from `src/mesh-names.json`, generated from the GLBs (`npm run mesh-names`, also run by `build-models`); `npm test` fails when it is stale. The search moves the camera and fades occluders through `Viewer.focusOn`, and reveals hidden parts only through the existing controls (group checkbox, peel slider), so the UI shows what changed.
- Step-through modes reuse the generic `Stepper`/`stepperBar` in `src/stepper.js` (←/→/Esc, "n / total"); the per-system Guide (`src/guide.js`) drives it and picks each part through the search's `pickResult` path, so hidden or peeled parts are revealed the same way. `scripts/guide.test.mjs` checks each layer's guide covers exactly its clickable parts. Stretching mode (`src/stretching-mode.js`) runs its own Stepper over `runOrder()`; only one stepper may run at a time, so starting either stops the other.
- Stretches are data in `src/stretches.json`, read only through `src/stretching.js` (README "Stretching data"); `scripts/stretches.test.mjs` requires an entry for every Muscular part and every action reversed by one of its stretches, so adding or changing a muscle means updating its entry.
- Posable layers (`posable` in their data: Skeletal `bones`; Muscular, Joints, Nervous, Senses `soft`) load as `PoseMesh` skinned meshes on one skeleton built from the bones (`src/rig.js`, README "Stretch poses"); play poses only through `Viewer.showPose`/`stopPose`, which hides the non-posable layers. Bounding-box helpers (`partCenters`, `focusOn`) use rest positions, so stop a pose before relying on them. The eye segments have no bones: they move to the sclera only once the Senses layer loads (`Poser.adopt` → `setEye`), so an eye pose needs that layer loaded.
- GLTFLoader turns spaces in node names into underscores, so read the original mesh name from `mesh.userData.name` (a glTF node extra).
