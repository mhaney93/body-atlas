# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Static Vite + three.js site, deployed by Vercel's Git integration (PRs get previews, `main` is production). There is no deploy workflow in this repo; Vite `base` is `/`.
- Body systems are data-driven layers (`src/layers.js` + `src/data/<system>.json`); README "Adding a body system" has the steps. Part info is keyed by the mesh name with "left"/"right" stripped. Optional generic layer fields (sub-`groups` and `groupToggles`, `shared` parts borrowed from another layer's model, `flow`, `effects` such as the haze glow, a guided `tour`, the `depthLevels` peel slider and `movements` picker built by `src/layer-controls.js`) are documented there too; any haze is decorative and must stay labeled "Illustrative". Every layer must fill a `notShown` list (README step 4; `scripts/not-shown.test.mjs` enforces it); when a change adds or drops parts, update that list. System models load lazily on first toggle unless the layer sets `preload: true` (only Skeletal does).
- `public/models/*.glb` are generated by `npm run fetch-data && npm run build-models` and committed. Don't hand-edit them; change `scripts/build-models.mjs` and rebuild. Each file has its own license (README "Anatomy model"); the CC BY-NC-SA ossicles and inner-ear nerves must stay in their own GLBs. The footer credits are a license requirement, so keep them.
- Parts BodyParts3D lacks come from Z-Anatomy: `scripts/extract-z-anatomy.py` runs in Blender and writes `data-sources/z-anatomy/` (committed), which the model build reads. Read evaluated meshes for objects with modifiers, or they export as stubs.
- Layer meshes must use `layerMaterials()` in `src/viewer.js` and be picked through `#hits()`, so the close-zoom cutaway (camera-distance discard) applies to both what you see and what you click.
- Viewer mesh visibility (sub-group toggles, peeling, movement emphasis) is applied in one place, `#applyDisplay` in `src/viewer.js`; set it through `setGroupVisible`/`setPeeled`/`setEmphasis`, not `mesh.visible`, or the controls overwrite each other.
- `npm run build-models` ends with `npm run check-placement` (also in CI, `.github/workflows/check.yml`): every layer in `src/data/` must stay under the skin, out of solid bone and out of other layers' parts. The build fixes placement in `scripts/settle.mjs` (and `fitLine`/`fitPoints` in `scripts/nervous-model.mjs` for nerves, `scripts/lymphatic-model.mjs` for lymph nodes); allowances live in `scripts/passages.mjs` and `scripts/overlaps.mjs` and must stay named and bounded. A full model build takes over an hour of CPU, so don't rebuild just to tweak check-only lists (`RESIDUALS`, `KNOWN`, `NESTED`), which the build does not read.
- Page-wide keyboard shortcuts must skip keys while the user types: reuse `isTypingTarget` from `src/keyboard-nav.js` (the WASD movement guard) rather than writing another check.
- The part search lists meshes from `src/mesh-names.json`, generated from the GLBs (`npm run mesh-names`, also run by `build-models`); `npm test` fails when it is stale. The search moves the camera and fades occluders through `Viewer.focusOn`, and reveals hidden parts only through the existing controls (group checkbox, peel slider), so the UI shows what changed.
- GLTFLoader turns spaces in node names into underscores, so read the original mesh name from `mesh.userData.name` (a glTF node extra).
