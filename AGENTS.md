# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Static Vite + three.js site, deployed by Vercel's Git integration (PRs get previews, `main` is production). There is no deploy workflow in this repo; Vite `base` is `/`.
- Body systems are data-driven layers (`src/layers.js` + `src/data/<system>.json`); README "Adding a body system" has the steps. Part info is keyed by the mesh name with "left"/"right" stripped. Optional generic layer fields (sub-`groups` and `groupToggles`, `shared` parts borrowed from another layer's model, `flow`, `effects` such as the haze glow) are documented there too; any haze is decorative and must stay labeled "Illustrative". System models load lazily on first toggle unless the layer sets `preload: true` (only Skeletal does).
- `public/models/*.glb` are generated by `npm run fetch-data && npm run build-models` and committed. Don't hand-edit them; change `scripts/build-models.mjs` and rebuild. Each file has its own license (README "Anatomy model"); the CC BY-NC-SA ossicles and inner-ear nerves must stay in their own GLBs. The footer credits are a license requirement, so keep them.
- Parts BodyParts3D lacks come from Z-Anatomy: `scripts/extract-z-anatomy.py` runs in Blender and writes `data-sources/z-anatomy/` (committed), which the model build reads. Read evaluated meshes for objects with modifiers, or they export as stubs.
- Layer meshes must use `layerMaterials()` in `src/viewer.js` and be picked through `#hits()`, so the close-zoom cutaway (camera-distance discard) applies to both what you see and what you click.
- After rebuilding the models, run `npm run check-nerves`: Z-Anatomy nerves are fitted onto BodyParts3D bones and then pushed under the skin and out of solid bone (`fitLine`/`fitPoints` in `scripts/nervous-model.mjs`); real foramina and canals are allowlisted in `scripts/nerve-passages.mjs`.
- GLTFLoader turns spaces in node names into underscores, so read the original mesh name from `mesh.userData.name` (a glTF node extra).
